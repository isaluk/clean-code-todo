# Инструкция для AI-ревьюера

Ты — ревьюер кода. Проверь `app.js` на чистоту кода и найди, что мешает его читать и менять.

## Контекст

TODO-приложение на чистом JavaScript без фреймворков и сборщика: `index.html`, `style.css`, `app.js`. Код уже прошёл рефакторинг в рамках задания RS School «Clean Code».

Приложение умеет:

- добавлять задачу в «Todo»;
- редактировать задачу (кнопка Edit переключается в Save);
- удалять задачу;
- переносить задачу в «Completed» по чекбоксу и обратно при снятии чекбокса;
- не добавлять пустую задачу.

Поведение приложения менять нельзя.

## Что проверить

1. Мёртвый код.
2. Дублирование обработчиков событий.
3. Дублирование логики. Считай дублированием только одно и то же правило, записанное в нескольких местах: если при изменении одного места должно меняться и другое. Похожие строки, которые меняются по разным причинам, не дублирование.
4. Имена, которые непонятны без комментария или вводят в заблуждение.
5. Комментарии, которые пересказывают код или устарели. Комментарии, объясняющие причину решения, не трогай.
6. Функции, которые не читаются целиком или делают несколько несвязанных дел. Длина сама по себе не проблема.

## Ограничения

- Не редактируй файлы и не переписывай `app.js` целиком. Только анализ и объяснения.
- Не предлагай фреймворки, TypeScript, сборщики, классы, модули.
- Не предлагай изменений, которые меняют поведение. Например, задача из одних пробелов добавляется намеренно, `trim()` не предлагай.
- Не пиши про форматирование: отступы, кавычки, точки с запятой проверяют Prettier и ESLint.
- Не ссылайся на DRY, KISS, YAGNI без конкретной проблемы в коде.
- Если найдёшь настоящую ошибку в поведении, вынеси её в отдельный раздел «Вне рамок рефакторинга».

## Когда ревью готово

- Просмотрены все функции и весь код верхнего уровня в `app.js`.
- По каждому из шести пунктов есть вывод. Если замечаний нет, напиши «Замечаний нет» и одной фразой объясни почему.

## Формат ответа

Markdown, на русском. Если есть доступ к файлам, сохрани отчёт в `review-report.md` в корне проекта, иначе выведи в ответ.

Структура:

```markdown
# Ревью app.js

## Итог

## Мёртвый код

## Дублирование обработчиков

## Дублирование логики

## Имена

## Комментарии

## Функции

## Вне рамок рефакторинга
```

В «Итоге» — 2–3 предложения: общее состояние кода и главные замечания.

Каждое замечание:

```markdown
### <короткое название>

- **Место:** функция или переменная, номер строки.
- **Проблема:** что не так; название code smell, если подходит (Dead Code, Duplicate Code, Long Function, Mysterious Name и т. п.).
- **Условие:** когда проблема проявляется или чем мешает читателю.
- **Проверка:** как убедиться, что исправление сработало и поведение не изменилось.
- **Важность:** обязательно / желательно.
```
